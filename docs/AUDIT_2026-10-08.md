# Полный аудит Sales OS — 2026-10-08

## Главный вывод

Проект имеет рабочую контентную и архитектурную основу, но пока не готов к надёжной повседневной эксплуатации без доработок. Основные проблемы — сохранность данных при нескольких вкладках, недостоверное сообщение о сохранении, неработающий Windows offline pack, переполнение всех страниц практики на телефоне и доступность навигации. Визуальный язык узнаваемо соответствует Vercel, однако соответствие приложенному контракту частичное.

**Зафиксировано 40 пунктов:** 10 P1, 28 P2 и 2 P3. Это не 40 одинаково критичных багов: реестр разделяет воспроизведённые дефекты, подтверждённые пробелы, инженерные риски и визуальные отклонения. Предложения новых функций вынесены отдельно. P0 не назначен: приложение в целом открывается и позволяет читать материалы.

Пользователь запросил аудит и фиксацию, а не реализацию исправлений. Продуктовый код, дизайн-система и учебные материалы не изменялись.

## Реестр P1 — первая очередь

### F01. Вторая вкладка перезаписывает прогресс первой

- **Тип:** воспроизведённый дефект, сохранность данных.
- **Место:** `src/scripts/app.js:5–16`, обработчик статуса, `persist()`; `ProgressWidget.tsx` слушает только локальное событие.
- **Сценарий:** открыть `01-001` и `02-001` в двух вкладках, отметить первый урок освоенным, затем второй. В сохранённом `lessonStatuses` остаётся только `02-001`. Каждая вкладка пишет целиком устаревший объект; обработчика `storage` нет. Посещение урока тоже вызывает запись всего состояния.
- **Влияние:** пользователь теряет отметки и потенциально закладки без предупреждения.
- **Рекомендация:** единый слой хранения с обновлением актуального состояния перед изменением, синхронизацией между вкладками и обработкой конфликтов. Одно добавление события без изменения модели записи недостаточно.
- **Приёмка:** обе отметки и обе закладки сохраняются при чередующихся действиях в двух вкладках; виджеты обновляются без reload.

### F02. Несохранённый ответ отмечается как сохранённый

- **Тип:** воспроизведённый дефект.
- **Место:** `src/scripts/app.js`, `notePut()` и таймер сохранения `[data-note]`.
- **Сценарий:** IndexedDB недоступен, запись note в localStorage выбрасывает `QuotaExceededError`. Toast сообщает об ошибке, но подпись становится **«Сохранено локально»**; введённого ответа в хранилище нет.
- **Влияние:** пользователь закрывает страницу, доверяя ложному подтверждению, и теряет ответ.
- **Рекомендация:** возвращать результат сохранения/пробрасывать ошибку, показывать устойчивое состояние «Не сохранено», сохранять dirty-buffer и предлагать выгрузку текущего текста.
- **Приёмка:** при отказе обоих хранилищ нет сообщения об успехе; текущий ответ можно скопировать/экспортировать до закрытия.

### F03. Офлайн-пакет Windows не устанавливается

- **Тип:** воспроизведённый дефект.
- **Место:** `scripts/after-build.mjs`, `walk()` и нормализация путей; `dist/assets/offline-files.json`.
- **Причина:** `path.join()` создаёт Windows-пути, а `replace(/^dist\//,'')` удаляет только POSIX-префикс. В манифест попадают `dist\\...` вместо URL.
- **Сценарий:** Настройки → «Загрузить офлайн-пакет»: **0 из 936 ресурсов**. `tests/test_offline_worker.mjs` падает на `Offline resource missing: dist\\`.
- **Рекомендация:** нормализовать путь относительно `dist` и разделители до формирования URL; проверять манифест на обеих ОС.
- **Приёмка:** все URL относительные и с `/`; полный пакет устанавливается, урок, практика, поиск и заметки работают при отключённой сети.

### F04. Все страницы практики переполняют мобильный экран

- **Тип:** воспроизведённый дефект адаптивности, WCAG 1.4.10 требует отдельной оценки табличного исключения и окружающего reflow.
- **Место:** `src/components/DocView.astro`, `src/styles/app.css`, `.article table` / `.table-wrap`.
- **Доказательство:** 72/72 страниц практики переполняют экран 390 px. На `18-P01` ширина документа **538 px**, таблицы **520 px**, viewport **390 px**. Таблица находится непосредственно в `article`, а не в `.table-wrap`.
- **Причина:** Python оборачивает таблицы в scroll-container, Astro `<Content />` — нет; CSS задаёт `min-width:520px`.
- **Влияние:** таблица и колонка баллов обрезаются, горизонтально перемещается вся страница.
- **Рекомендация:** единая обработка Markdown-таблиц для Astro; локальная прокрутка или мобильное представление с сохранением заголовков.
- **Приёмка:** нет переполнения документа 320/390/768 px; таблица полностью доступна клавиатурой и касанием.

### F05. Закрытое мобильное меню остаётся в Tab-порядке

- **Тип:** воспроизведённый дефект доступности, WCAG 2.4.3/2.4.7.
- **Место:** `src/layouts/Shell.astro`, `src/scripts/app.js` `toggleMenu()`, mobile CSS sidebar.
- **Сценарий:** на телефоне нажимать Tab с начала страницы. После skip-link фокус переходит на закрытие меню и пункты sidebar с координатами **x = −78 / −284 px**. Меню только перемещено `transform` за экран.
- **Рекомендация:** делать закрытую навигацию недоступной для фокуса и accessibility tree, корректно переключать `inert`/видимость при breakpoint.
- **Приёмка:** закрытый drawer не содержит доступных Tab-целей; клавиатура сразу достигает видимых действий.

### F06. Открытый drawer не управляет фокусом и прокруткой

- **Тип:** воспроизведённый пробел взаимодействия.
- **Место:** `toggleMenu()`, `.mobile-shade`, `.side`.
- **Доказательство:** после открытия фокус остаётся на «Открыть меню»; `body overflow: visible`, `main` не inert, модальная семантика отсутствует. Escape закрывает меню, но полноценного управления фокусом нет.
- **Влияние:** клавиатура/скринридер могут продолжать работать с затемнённой страницей; фон прокручивается.
- **Рекомендация:** выбрать модальное поведение drawer, переносить фокус внутрь, ограничивать фон, возвращать фокус триггеру, блокировать scroll. Обеспечить немодальный вариант только если он явно спроектирован.
- **Приёмка:** Tab/Shift+Tab, Escape, закрытие кнопкой/подложкой и смена breakpoint сохраняют ожидаемый фокус.

### F07. Планшетная навигация превращается в неназванные иконки

- **Тип:** подтверждённый дефект доступности, WCAG 4.1.2.
- **Место:** `Shell.astro`, CSS breakpoint 769–1050 px.
- **Доказательство:** при 1024 px подписи шести основных ссылок скрыты `display:none`; SVG `aria-hidden=true`; `aria-label` и `title` отсутствуют. Нет и доступного переключателя для раскрытия всей программы.
- **Влияние:** невозможно узнать назначение иконок через screen reader; новичок должен угадывать разделы.
- **Рекомендация:** доступные имена независимо от текстовой видимости, подсказки для мыши/фокуса, явный доступ ко всей программе в collapsed-режиме.
- **Приёмка:** каждая ссылка имеет понятное accessible name на 768/1024/1050 px.

### F08. Мелкий текст светлой темы не проходит контраст

- **Тип:** измеренный дефект доступности, WCAG 1.4.3.
- **Место:** CSS `--subtle`, `.breadcrumb`, `.footer`, `.item .number`, `.badge.warning`.
- **Измерения:** `#888` на белом **3,54:1** для 11–12 px; warning **3,75:1** на собственной подложке. Требование для обычного текста — 4,5:1.
- **Влияние:** плохо читаются навигация, ID и редакционная маркировка. Это информативный текст, а не декоративные детали.
- **Рекомендация:** доступные semantic text-tokens и проверка всех badge-вариантов по фактическому фону.
- **Приёмка:** нормальный значимый текст ≥4,5:1 в обеих темах. Нельзя объявлять нарушение допустимым только потому, что `#888` присутствует в дизайн-файле.

### F09. Обязательный Astro type-check не проходит

- **Тип:** повторно воспроизведённый дефект сборочной приёмки.
- **Место:** `package.json`, `playwright.config.ts:7`, `src/pages/final-project/index.astro:3–4`.
- **Доказательство:** `npx astro check`: **3 errors** — `process`, `node:path`, `node:fs/promises`; отсутствуют типы Node.js. Production build ранее прошёл, что не устраняет ошибки type-check.
- **Влияние:** CI останавливается до дальнейших gates; проект нельзя считать полностью проверенным.
- **Рекомендация:** объявить нужные типы и проверить их включение в TS-конфигурацию; не исключать файлы лишь ради зелёного отчёта.
- **Приёмка:** check на чистом checkout проходит на поддерживаемых Windows и Linux.

### F10. Итоговый проект существует, но недоступен из навигации

- **Тип:** подтверждённый функциональный пробел.
- **Место:** `Shell.astro`, `src/pages/practice/index.astro`, `src/pages/index.astro`.
- **Доказательство:** во всех 475 HTML найдено **0 входящих ссылок на `/final-project/`**. Ни sidebar, ни каталог практики не дают перехода.
- **Влияние:** пользователь не узнаёт о важной итоговой части курса без знания URL.
- **Рекомендация:** явная точка входа в практике и учебном маршруте; обозначить ожидаемый результат и рекомендуемые подготовительные модули.
- **Приёмка:** новый пользователь доходит до итогового проекта через интерфейс, без ручного ввода URL.

### Внутренние противоречия эталона

1. Таблица gray-scale и semantic border-table местами дают разные dark-значения. При исправлении использовать семантические роли компонентов и зафиксировать выбор.
2. Эталон разрешает мелкий `#888` как caption, но сам указывает его провал AA. Значимый текст не становится декоративным из-за размера: доступность имеет приоритет.
3. Есть правила «pills только badges», но progress и avatars тоже используют округление. Нельзя автоматически объявлять текущий округлый progress несоответствием.
4. Пример Tailwind config относится к прежней конфигурационной модели; проект на Tailwind 4. Переносить значения токенов, а не копировать устаревшую конфигурацию.

### Взаимодействия: Before / After

Это рекомендации, реализация не выполнена.

| Before | After | Why |
|---|---|---|
| Drawer с `transform`, фокус остаётся снаружи | Видимость/inert, перенос фокуса, возврат триггеру, 150–200 ms ease-vercel | Убирает невидимый фокус и делает пространственное поведение понятным |
| «Сохранено» после любого завершения `notePut()` | saving → saved / failed с сохраняемым dirty-buffer | Обратная связь отражает настоящий результат |
| Маленький status/badge конкурирует с заголовком row | Mobile meta-row, ясная press/focus-area, без пружин | Повышает читаемость и точность касания |
| Все toast исчезают через 3,5 s | Короткий success; стойкая inline-ошибка с действием | Ошибка потери данных не должна зависеть от чтения быстрого toast |
| Progress анимирует `width` | При необходимости `scaleX` с origin left, reduced-motion | Необязательная оптимизация; не утверждается измеренный fps-дефект |

Bundled detector дал два сигнала: левую границу blockquote и анимацию width. **Blockquote — допустимая структура цитаты/результата, ложноположительный AI-антипаттерн.** Width-transition прогресса — низкоприоритетная рекомендация, не основание для крупной переписи.

## Рекомендуемая последовательность работ

1. **Сохранность и работоспособность:** F01–F03, F09, связанные F11–F17. Регрессионные сценарии storage, импорт, fallback и offline.
2. **Общий UI-фундамент:** F04–F08, F18–F29. Сначала tokens/fonts, потом Shell, drawer, EntryRow, controls, таблицы, настройки. Это устранит множество повторяющихся дефектов сразу.
3. **Учебная полнота:** F10, F30–F34, A01/A03. Доступный итоговый проект, модульные главы, библиотека, ясный следующий шаг.
4. **Редакторская работа:** предметные критерии, примерные решения, provenance, актуализация областей права/платформ. Не объявлять «полностью verified» по итогам frontend-работы.
5. **Доставка и QA:** F35–F40. Воспроизводимые зависимости, один canonical pipeline, обновлённая документация, production preview и smoke на реальном хостинге.
6. **Финальный polish по Vercel:** повторная матрица light/dark, 320/390/768/1024/1440, все семейства страниц, клавиатура, fonts/contrast и реальный offline. Новые функции — после надёжного основания.

Это соответствует последовательности Impeccable harden → adapt/layout/typeset/colorize → optimize → audit → polish; названия workflow служат ориентирами, а не заменяют конкретные задачи выше.

## Что уже сделано хорошо

- Статический HTML остаётся читаемым без собственного backend; нет отправки личных ответов на API проекта.
- Контент хранится в исходном Markdown, 430 копий совпадают с оригиналами; ID устойчивы и пригодны для миграций.
- Все основные маршруты открываются; внутренняя ссылочная структура проверена, модульные списки не смешивают чужие уроки.
- Vercel-основа узнаваема: монохром, тёмный `#fafafa`, border surfaces, аккуратные радиусы, отсутствие декоративных градиентов и bounce.
- Тема, статус, обычное сохранение заметки и bookmark переживают reload; нормальные v1/v2 import/export работают, включая FINAL_PROJECT-note.
- Import v2 проверяет ID/статусы и rejects inherited keys; пользователь подтверждает замену данных.
- Самооценка не выдаётся за независимую аттестацию; `editorial_draft` маркирован честно.
- Есть skip-link, focus-outline, reduced-motion и обозначенные textarea. Эти механизмы нужно довести, а не заменять ради визуальных эффектов.
