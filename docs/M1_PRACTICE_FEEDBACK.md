# M1 — подсказки, разборы и сравнение итераций

Дата: 2026-10-09. Техническая реализация проверена. Независимая редакционная приёмка и проверка учебной пользы открыты. M2–M8 не реализовывались.

## Объём

Подготовлены разборы для `03-P01`, `03-P03`, `05-P03`, `06-P01`, `06-P02`, `08-P02`, `08-P03`, `11-P01`, `12-P03`, `13-P02`: выбор ниши и клиента, исследование компаний, первое сообщение и follow-up, discovery и брифы, коммерческое предложение, возражения и скидка.

Каждый содержит три подсказки, слабый/приемлемый/сильный пример, объяснение всех пяти критериев, три типичные ошибки с исправлениями и альтернативный подход. Всего: 30 примеров, 150 объяснений, 30 подсказок, 30 ошибок и 10 альтернатив.

Примеры раскрываются по желанию, в том числе до первого ответа. Просмотр не меняет статусы, самооценку или историю. Вымышленные компании, расчёты и диалоги явно обозначены как учебные; они не подтверждают выполнение заданий, требующих реальных случаев. Для остальных 62 практик и итогового проекта честно показано отсутствие готового разбора; редактор полностью доступен.

Сравнение работает во всех 72 практиках и итоговом проекте. После двух сохранений выбираются первая и последняя итерации; можно выбрать другую пару. Показаны даты, ответы, самооценка, следующий шаг и исходные формулировки критериев. Изменение рубрики сопровождается предупреждением о несопоставимости оценок. Пустая история, одна попытка и выбор одинаковых итераций имеют отдельные состояния. Изменение текста не выдаётся за улучшение качества.

## Архитектура и сохранность

- Источник: `sales-knowledge-base/practice-guides.json`, схема 1; устойчивые ID практик и критериев, версия и редакционный статус каждого разбора.
- `scripts/practice_feedback.py` проверяет полноту и точное соответствие рубрик исходным заданиям, экранирует текст и формирует общий HTML для Astro и Python. Изменение рубрики требует пересмотра разбора и останавливает сборку до согласования.
- Расширен существующий `PracticeWorkspace.astro`. `practice-feedback.js` читает единый user-store после его загрузки, не записывает оценки или личные данные и обновляется при межвкладочной замене состояния.
- IndexedDB, миграции и `sales-os-v3` не менялись. Снимки истории остаются неизменными. Экспорт/импорт и восстановление работают через существующий центр резервных копий.
- Публичные разборы включены в Pagefind и JSON fallback. Личные ответы не попадают в публичный индекс. Новый скрипт получает адрес с хешем содержимого и входит в полный offline-пакет.
- Используются существующие Vercel-токены и темы. Подсказки — нативные `details/summary`; выбор итераций — подписанные `select`. Длинный текст переносится, узкое сравнение становится одноколоночным. Исправлено переполнение мобильной шапки при классической полосе прокрутки.

## Выполненные проверки

- `npm run lint`, `npm run check`: успешно; ошибок/предупреждений Astro нет, остаются три прежние подсказки deprecated `BeforeUnloadEvent.returnValue`.
- `npm run build`: 482 маршрута, 467 Pagefind-документов, 1 020 offline-ресурсов. Python fallback: 481 сгенерированный документ, 467 поисковых записей, 502 offline-ресурса.
- `npm run test:quality`, `npm run test:fallback`: успешно в ходе реализации. После финальных изменений повторены обе сборки и адресные E2E M1; статические/offline gates также повторены.
- `python tests/test_practice_feedback.py`: три теста структуры, соответствия рубрик, отклонения недостоверного verified-статуса и экранирования.
- `tests/e2e/practice-feedback.spec.ts`: **4/4 на Astro production preview и 4/4 на Python fallback**. Проверены все десять разборов, клавиатура, отсутствие изменений прогресса при чтении, две попытки, reload, настоящий export/import backup, изменённая рубрика, пустые/длинные ответы, безопасный вывод HTML-подобного текста, межвкладочное обновление, поиск и работа без сети после установки полного пакета.
- Сравнение проверено в двух темах при 320, 375, 390, 768 и 1440 CSS px. Встроенный браузер подтвердил читаемость подсказок и отсутствие переполнения при ширине документа 375 px с классической полосой прокрутки.
- Пять существующих адресных E2E контекста маршрутов, поиска, миграции IndexedDB, истории и объединения/восстановления backup прошли.
- Снимки: `docs/screenshots/m1-feedback/`. Сравнение содержит намеренно длинные HTML-подобные тестовые ответы — это проверка устойчивости, не пользовательские данные.

## Открытые условия полной приёмки

1. Компетентный независимый редактор должен проверить все десять разборов вместе с заданиями, включая расчёты, ограничения и соответствие каждому критерию. В [редакционном workflow](../sales-knowledge-base/EDITORIAL_REVIEW_WORKFLOW.md) прямо указано: «Автоматический тест или языковая модель не являются рецензентом». Сейчас `humanReviewer` и `role` пусты; все разборы `editorial_draft`. Авторская сверка и технические тесты не заменяют такую приёмку.
2. Провести пользовательский тест: самостоятельный ответ → разбор → новая итерация → объяснение, что улучшилось и на какой критерий опирается изменение. Эффективность обучения пока не измерена. Долю повторных попыток можно получить локально из существующей истории: количество практик с минимум двумя итерациями / количество практик хотя бы с одной. Автоматическая аналитика не внедрялась; эта доля сама по себе не доказывает роста качества.

До выполнения этих условий M1 технически поставлен, но не обозначается полностью принятым. Общий редакционный gate курса этим изменением также не закрывается.
